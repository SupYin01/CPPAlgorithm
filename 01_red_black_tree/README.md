# 01 · 红黑树（Red-Black Tree）练习项目

亲手实现插入与查找，体会三件事：

1. 红黑树如何用 **染色 + 少量旋转** 把朴素 BST 最坏 O(n) 的退化死死压回 O(log n)；
2. 红黑树 vs AVL：AVL 更"端正"（更矮、查找常数略小），红黑树更"省事"
   （更新时旋转更少）—— 各有取舍，没有全面碾压；
3. 口诀（根叶黑、不红红、黑路同）每一条到底在防什么、由谁来保证。

---

## 先背口诀（validate() 会逐条替你检查）

| 口诀   | 精确含义                                             | 由谁保证                                   |
| ------ | ---------------------------------------------------- | ------------------------------------------ |
| 根叶黑 | 根结点是黑的；所有叶子（NIL 哨兵）是黑的             | 构造函数 + insertFixup 收尾把根染黑；哨兵生来是黑 |
| 不红红 | 红结点的孩子必是黑（不存在相邻的两个红）             | insertFixup 的全部工作                     |
| 黑路同 | 任一结点到它的每个 NIL 的路径上，黑色结点数相同      | 修复只"变色上推 / 旋转"，从不改变路径的黑高 |

外加一条与颜色无关的本分：BST 有序（左 < 我 < 右）。
**推论**：黑路同 ⇒ 黑高 ≤ log₂(n+1)；不红红 ⇒ 最长路径 ≤ 最短路径的 2 倍
⇒ 树高 ≤ 2·log₂(n+1)。这就是红黑树"平衡"的全部来源，也是它比 AVL 松的原因。

## 三棵树对比（测试第 5、6 节会亲手量出来）

|                | 朴素 BST      | AVL                      | 红黑树                          |
| -------------- | ------------- | ------------------------ | ------------------------------- |
| 平衡标准       | 无            | 每个结点左右高度差 ≤ 1   | 黑路同（宽松得多）              |
| 最坏高度       | n（退化链表） | ≈ 1.44·log₂n             | ≤ 2·log₂(n+1)                   |
| 查找           | 最坏 O(n)     | O(log n)，常数最小       | O(log n)，稍深一点点            |
| 插入调整       | 无            | 旋转更频繁（总量更多）   | 旋转 ≤ 2 次，且发生得更少       |
| 删除调整       | 无            | 最坏 O(log n) 次旋转     | 旋转 ≤ 3 次（O(1)）             |
| 典型应用       | 教学          | 查多改少的场景           | `std::map/set`、Linux 内核、Java TreeMap |

一句话：**AVL 查找略快，红黑树改起来更省** —— 这正是 `std::map` 选红黑树的原因。

## 调试锦囊

- `t.validate(&err)` 会告诉你**违反了哪条口诀**；`t.draw()` 侧向打印树形（[R]/[B] 标色）；
- `t.rotations()` 统计旋转次数，可以给你的 fixup 加日志对照预期；
- 常见 bug Top 5：
  1. 旋转后忘记把"x 原来的父亲"接到新子树根上；
  2. 忘记处理 `x->parent == nil_`（旋转的其实是根）；
  3. 判等写成 `key == node->key`（本实现没有 `==`，用"互不小于"）;
  4. fixup 情况2 左旋后忘记重新取 `z` 的父亲；
  5. 新结点染成黑色（直接破坏黑路同，且无法局部修复）。

## 思考题

1. 插入时情况1 可以把红色一路推到根，为什么旋转次数却始终 ≤ 2？
2. 用"最短路径全黑、最长路径红黑相间"推出树高 ≤ 2·log₂(n+1)。
3. 红黑树查找代码与普通 BST 完全相同，那"红黑树查找快"快在哪、
   比 AVL 又差在哪？（提示：测试第 5 节的树高与耗时数据）
4. 为什么 `std::map` 用红黑树而不是 AVL？（想想插入/删除的调整成本 vs 查找收益）
